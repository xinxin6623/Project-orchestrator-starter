# 任务拆解

## 拆解原则

- 原子任务粒度: 10-30 分钟可完成
- 最大并行 Worker: 3
- 串行任务由 Supervisor 自任，并行任务派 Worker
- 每个模块产出必附【设计意图】段（来源: constraints `require_design_rationale: true`）

## 依赖关系图

```
S1. 整体框架与价值主张 (Supervisor)
  │
  ├──► W1. 产品功能 + 3R 标注段 (Worker, 并行)
  ├──► W2. 商业计划 5P + 竞品 + 成本双轨段 (Worker, 并行)
  └──► W3. 科学探究：数据联动 + 科普课堂 + 光伏原理段 (Worker, 并行)
  │
  ▼
S2. 跨模块衔接 + 叙事线设计 (Supervisor)
  │
  ├──► W4. 视频脚本框架 四段式精确到秒 (Worker, 并行)
  ├──► W5. 人员分工 + 原材料 + 安全提示 + 宣传语 (Worker, 并行)
  └──► W6. 答辩预设 + 服务人群 + 提交自查清单 (Worker, 并行)
  │
  ▼
S3. 评价体系总框架 + Rubric 自查 (Supervisor)
  │
  ▼
S4. 最终整合 → final.md (Supervisor)
```

## Worker 派工 5 段模板（S1 完成后注入）

每个 Worker 接收:
1. **身份**: "你是绿光森林科技公司的 [对应角色]，正在帮一支小学生团队撰写北京市第十二届小学生绿色创新挑战赛的规划书模块"
2. **任务定义**: 具体模块的内容要求和边界（来自上表）
3. **输入依赖**: 指定文件路径（01-frame.md / 00-input.md / 02-anchor.md 中相关段落）
4. **输出格式**: Markdown，每个子段末尾附 `> **设计意图**：<为什么这样写/解决什么问题/依据什么标准>`
5. **边界**: 不越界写其他模块内容、不引入未经 Frame 确认的假设、语言适配五年级学生、字数控制在规划书相应段落合理范围内
