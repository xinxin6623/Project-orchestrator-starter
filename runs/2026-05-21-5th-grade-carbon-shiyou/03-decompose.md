# 任务拆解清单

## 耦合性扫描结论

本项目共识别 **10 个任务**，其中:
- **tight（串行，Supervisor 自任）**: 4 个 —— 涉及叙事一致性、价值主张、整体框架的工作
- **loose（并行，Worker 可派）**: 4 个 —— 独立信息检索任务，无相互依赖
- **medium（串行但共享上下文，Supervisor 自任）**: 2 个 —— 依赖前序产出 + 需保持风格一致

**耦合性裁决理由**:
- 整体框架、活动主线、评价体系、最终整合 → tight：方案的"骨架"和"价值线"必须由 Supervisor 一手把控，分散后容易碎片化
- 政策检索、学情资料、案例收集、时令资源 → loose：各自独立，按主题分头查即可
- 每环节教师手册、安全资源清单 → medium：依赖前序产出（主线+素材），但都是 Supervisor 一人完成，无需并发

## 派工计划

**第一批并发（loose）**: 2.1, 2.2, 2.3, 2.4
- 4 个 Worker 同时派发，但受 `max_parallel_workers: 3` 限制 → **分两轮**：
  - 轮一：2.1, 2.2, 2.3（3 个并发）
  - 轮二：2.4（完成轮一后单发）
- 每个 Worker 必须注入 §6.2 的 5 段提示词

**第二批串行（tight + medium）**:
1.1 → 3.1 → 4.1 → 4.2 → 5.1 → 5.2

**注**: 1.1 可以与 loose 批次并行（Supervisor 自任 + Worker 并发），因为 1.1 不依赖任何 Worker 产出。

## 时间预算

- loose 批次（含派工开销）: ~35min（受并发限制）
- tight + medium 批次: 25+30+40+25+25+15 = 160min
- **总预估**: ~195min（约 3.25 小时）

按 constraints.md `atomic_duration_minutes: [10, 30]`：4.1（40min）略超上限，已识别但保留——因为是 4 环节×10min 的合并任务，强行拆分会破坏风格一致性（属于明显需要 Supervisor 自任的 medium）。

## 耦合性扫描理由（显式陈述）

为什么 1.1（整体框架）必须 tight 而不是 loose：
> 框架决定整个方案的叙事线、目标分层、对象适配。如果派 Worker 做，Worker 会按"通用低碳方案"模板套，丢失"5 年级 + 石油附小 + 秋季 + 校内 + 央企背景中性"这些约束。Supervisor 必须基于 01-frame.md 亲自定调。

为什么 3.1（活动主线）必须 tight：
> 3-4 个环节要在叙事上递进、在认知负载上爬升、在时长上拼合——这是典型的"全局视野"工作，分给 Worker 会出现环节碎片化、衔接不顺。

为什么 4.1（每环节手册）是 medium 而不是 tight：
> 已经有 3.1 主线定型后，写每个环节的四段式手册是"沿着既定结构填内容"的工作，强度高但全局判断少。Supervisor 自任但不需要等多个并行产出汇聚。

为什么 5.1（最终整合）必须独立 tight：
> CLAUDE.md §5.3 第 4 条强制——整合不是免费的。前序产出有各自体例，整合需要重新统一卷首语口吻、章节衔接、术语一致。
